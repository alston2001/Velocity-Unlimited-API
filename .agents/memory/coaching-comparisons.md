---
name: Coaching comparisons
description: Rules for selected-exercise historical comparisons and resilient coaching output.
---

Coaching must never depend on an AI response being available. The server should return a concise, data-grounded fallback that states the load-matched velocity comparison, velocity loss, readiness (when supported), and a practical next-set action.

**Why:** A blank or generic coach section makes a valid recorded set unusable when the model is unavailable. Showing the calculation and recommendation makes the app useful even then.

**How to apply:** Compare only valid historical sessions for the selected exercise at a similar load (±15%). State faster/slower as a percentage only when a baseline exists; otherwise clearly say that history is insufficient. Keep Squat's seeded history limited to the demo path while arbitrary exercise names build their own history.
